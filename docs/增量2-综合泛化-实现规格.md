# 增量2 综合泛化 实现规格

> 依据：《dsh-memory-architecture-final-design.md》v1.1 §16.2（增量2）+ §9（CLS 归纳泛化）。
> 动机（红2）：复盘只做"抽取"（events→facts），没做"综合"（facts→traits 的归纳泛化）。根因：`selfPattern='附和'` 粒度太粗，把多条语义迥异的自述共用一桶，导致负面特质被错误固化。

## 0. 目标与范围

在复盘流程补上 CLS"皮层归纳"这一半：**从关于她的多条语义事实（facts）归纳出稳定特质候选**，并用「≥2 个不同证据组」的机制闸门拦住"单条经历被误归纳成稳定模式"。

**本轮做**：① `review.ts` 加 generalize 步骤（新 prompt）；② 机制闸门 `requireGeneralizationEvidence`（≥2 不同事件证据）；③ 泛化 traits 候选复用 P2 的 `commitCandidates` 落 `candidateTraits`。

**明确不做**：不引入新持久化层（复用 candidateTraits）；不做 confidence 上限机制（candidateTraits 是 string[]，无 confidence，留后续）；不改 reflectSelf（它继续负责"即时表达反思"）。

## 1. 流水线定位（区分 reflectSelf）

| 步骤 | 输入 → 输出 | 职责 |
|---|---|---|
| distillFacts | events → facts（type=user/world/self） | 抽取（海马快记） |
| **generalize（新增）** | **type=self 的 facts → traits 候选** | **综合（皮层归纳）** |
| reflectSelf | events → speakingStyle/narrative/即时表达 | 即时自我表达反思 |
| decidePromotion | traits 候选 → stable/candidate | 晋升闸门（P2 已有） |

generalize 与 reflectSelf 互补不重复：reflectSelf 从"当日事件"反思即时表达；generalize 从"当日语义事实"归纳稳定特质（须 ≥2 证据）。

## 2. 改动点 1：`src/review.ts`

### 2.1 新增 `GENERALIZE_PROMPT`

```
你是反思端模型。基于下面列出的"关于你自己的语义事实"，归纳出你的稳定特质，只输出 JSON。
格式：{"traits":[{"trait":"特质陈述","sourceFactIds":["事实id"]}]}
归纳规则：
1. 每条特质必须由至少 2 条不同的语义事实共同支持（把 sourceFactIds 里对应的事实 id 都列出来）；只有单条事实支持的不算特质，不要输出。
2. 归纳"稳定模式"，不是复述单条事实；用描述性陈述（如"我倾向于先澄清再回答"），禁止祈使句、禁止预设行为规则。
3. 若事实之间有相互矛盾，不要把它们归纳成同一条特质。
4. sourceFactIds 必须逐字取自下面列出的事实 id，不要编造。
没有可归纳的特质就输出 {"traits":[]}。
```

### 2.2 新增 `generalize` 方法（仿 distillFacts 的降级姿态）

```ts
/** step2.5 综合泛化：从 type=self 的 facts 归纳稳定特质（≥2 证据） */
async generalize(facts: PersonaFact[]): Promise<{ trait: string; sourceEventIds: string[] }[]> {
  const selfFacts = facts.filter((f) => f.type === 'self');
  if (selfFacts.length < 2) return [];   // 少于 2 条自我事实，无从综合
  const listing = selfFacts.map((f) => `- [${f.id}] ${f.content}`).join('\n');
  const raw = await this.deps.llm.complete({ role: 'reflect', prompt: `${GENERALIZE_PROMPT}\n\n语义事实：\n${listing}` });
  const parsed = this.parseJsonLoose(raw);
  if (!parsed || !Array.isArray(parsed.traits)) return [];
  // 机制闸门：每条 trait 的支持事实去重后 ≥2 个不同事件，否则丢弃（防单条误归纳）
  const byId = new Map(selfFacts.map((f) => [f.id, f]));
  return parsed.traits
    .filter((t: any) => t && typeof t.trait === 'string' && Array.isArray(t.sourceFactIds))
    .map((t: any) => ({
      trait: String(t.trait).trim(),
      sourceEventIds: [...new Set(t.sourceFactIds
        .filter((id: unknown): id is string => typeof id === 'string')
        .flatMap((id: string) => byId.get(id)?.sourceEventIds ?? []))],
    }))
    .filter((g) => g.trait && g.sourceEventIds.length >= 2);  // ← 核心机制约束
}
```

### 2.3 `run()` 接线

在 `distillFacts`（step2）之后、`reflectSelf`（step3）之前插入：

```ts
// step2.5 综合泛化（增量2）：type=self facts → 稳定特质候选（≥2 证据），进 candidateTraits
let generalizedTraits: string[] = [];
try {
  const gens = await this.generalize(out.facts);
  out.cost.llmCalls = 2;   // generalize 占用一次 LLM 调用（后续步骤计数顺延，见注意）
  generalizedTraits = gens.map((g) => g.trait);
} catch {
  generalizedTraits = [];  // 泛化失败不阻断复盘
}
```

> **注意（成本口径）**：`llmCalls` 现有语义是"核心三步（distillFacts/reflectSelf/updateMirror）"，generalize 是第 4 个核心调用。为不破坏既有观测口径（`out.cost.llmCalls` 被断言锁定为 1/2/3），generalize 的调用**不并入 llmCalls**，改在 `cost` 里新增 `generalizeCalls: number`（见改动点 3），与 P2 的 `memoryFactCalls` 同款"单独计"理由。上面 `out.cost.llmCalls = 2` 那行**删掉**，改为 `out.cost.generalizeCalls = 1`。

### 2.4 泛化结果落 candidateTraits

在 P2 晋升闸门那段（`decidePromotion` 之前）之后、`commitCandidates` 之前，把 generalizedTraits 一并并入候选：

```ts
// 增量2：generalize 的泛化特质与 reflectSelf 的 traits 候选一起去重后进 candidateTraits
const candidateTraits = [...new Set([...(diff.traits ?? []), ...generalizedTraits])];
```
（即把现有 `const candidateTraits = diff.traits;` 这一行替换为上面这行，后续 decidePromotion/commitCandidates 逻辑不变——泛化特质与即时特质同过同一晋升闸门、未过门槛同样隔离。）

> **边界兜底（2026-11 施工中补）**：当 `diff.traits` 为空、仅 `generalizedTraits` 非空且 `decidePromotion` 判 `promote=true`（reflectEvents 含 user_direct 且跨 ≥2 日期）时，泛化特质既不进 stable（它从不写入 diff.traits）、原 commitCandidates 分支又被 `!promote` 短路——会被静默丢弃。故 commitCandidates 的落库改为：`promote=false` 落全部候选、`promote=true` 落 `generalizedTraits`，确保泛化产物永不丢失（它来自 type=self facts，只落 candidate、不直接 stable）。

## 3. 改动点 2：`src/types.ts`

`ReviewOutput.cost` 新增：
```ts
/** 增量2：综合泛化这一步的 LLM 调用数（单独计，不并入 llmCalls，理由同 memoryFactCalls） */
generalizeCalls: number;
```
并在 `run()` 初始化 `out.cost` 处补 `generalizeCalls: 0`。`ReviewOutput` 不需要新增其他字段（泛化产物并入 candidateTraits，不单独暴露）。

## 4. 测试（新增 `tests/generalize.test.mjs`）

用 mock LLM 直接测 `generalize` 方法（不依赖真实 LLM）：

1. self facts <2 → 直接返回 []（不发 LLM 调用）。
2. 2 条 self facts、LLM 返回 1 条 trait 关联 2 条 fact → 通过，sourceEventIds 去重后 ≥2。
3. trait 只关联 1 条 fact（或该 fact 只有 1 个事件）→ 被「≥2 事件」闸门丢弃。
4. trait 的 sourceFactIds 含未知 id → 该 id 被忽略，若剩余证据 <2 → 丢弃。
5. LLM 返回非 JSON → 返回 []（降级）。
6. 泛化结果与 reflectSelf traits 去重合并进 candidateTraits（跑一次 run 或单测合并逻辑）。

## 5. 验收

- `npm run build` exit 0；`npm test` 全绿（现有 305 + 新增 generalize 用例）。
- `generalize` 产出的每条 trait 的 sourceEventIds 去重后 ≥2（机制闸门可证）。
- 单条事实支持的特质被丢弃（防单条误归纳，红2 根因的机制层修复）。
- 泛化特质与即时特质同过 P2 晋升闸门、未过门槛同落 candidateTraits（不直接 stable）。
- `cost.generalizeCalls` 单独计数，`llmCalls` 口径不变（既有断言不破）。
- 边界 A 兜底：`promote=true` 且 `diff.traits` 为空时，泛化特质仍落 candidateTraits（不被静默丢弃）。
