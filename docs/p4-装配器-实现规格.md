# P4 装配器（按意图构造工作记忆）实现规格

> 依据：《dsh-memory-architecture-final-design.md》v1.1 §5 契约三（283-299 行）+ §10 P4 行（382 行）+ §6 混合检索流水线。
> 动机：现有 `buildInjection` 是"机械五槽装配"（recall.ts `assembleRecall`），只读 `events` + `openThreads`，**不读 facts/attributes/self_model**（装配级缺口，attributes 一条都没进注入）。契约三要求"按意图构造工作记忆，不让任何一层永久当主干"。

## 0. 目标与范围

把注入从"机械五槽"升级为"按意图装配"：先判意图，再按意图选主读层、定预算、过配额闸门，产出带标签工作记忆。**本轮以 shadow 形式落地**——新装配器与旧 `buildInjection` 并行跑，产出差异记录但不切读，直到 §11.2 指标达标 + 用户拍板才 feature flag 切过去。

**本轮做**：
1. `src/intent.ts`（新）：规则优先的意图解析器（零 LLM，注入是每轮热路径）。
2. `src/assembler.ts`（新）：按意图装配器（意图 → 主读层 → 预算 → 配额闸门 → 带标签工作记忆）。
3. shadow 运行：`index.ts` 注入调用点并行跑新旧，差异写观测文件，注入仍走旧路径。
4. feature flag：配置开关，一键切回/切到新路径。

**明确不做**（留后续）：
- 不做向量召回/图投影（那是 P5/P6，契约三里"向量只找候选"不在本轮）。
- 不做意图解析的 LLM 版本（规则优先即可；LLM 意图识别留观察期后再评估）。
- 不切读——shadow 期间注入文本仍由旧 `buildInjection` 产出。

## 1. 意图解析器（`src/intent.ts`）

### 1.1 意图枚举

```ts
export type Intent =
  | 'continue_task'   // 继续当前任务 / 未结事项
  | 'fact_lookup'     // 当前偏好 / 属性 / 承诺 / 知识更新
  | 'history_replay'  // 历史回放（当时发生什么 / 谁说过什么 / 原话）
  | 'persona'         // 人格 / 风格 / 自我叙事
  | 'fuzzy';          // 模糊回忆 / 跨事件发现
```

### 1.2 判定规则（规则优先，零 LLM）

```ts
export interface IntentHit {
  intent: Intent;
  /** 命中的线索词（观测用，便于调规则） */
  hits: string[];
  /** 主意图（0 号）与可选第二意图（1 号），最多 2 个 */
}

export function resolveIntent(cueText: string, hasOpenThread: boolean): IntentHit[]
```

判定顺序（先命中的规则优先，返回主意图 + 可选第二意图，**最多 2 个**）：

1. **history_replay**：含时间词（那天/上次/之前/当时/那时候/前几天/昨天/上周/还记得吗/曾经/以前）或历史词（说过/提过/原话/怎么说的/当时怎么）。
2. **persona**：含人格词（你是什么样/你觉得自己/你的性格/你是谁/你偏好什么风格/你说话方式/你记性）。注意：`你是谁` 这类自我认知词 → persona，不是 fact_lookup。
3. **continue_task**：含任务续接词（继续/接着/上次说到/那个任务/进度/接下来/回到刚才）或 `hasOpenThread === true`（有未结 thread 时默认续接）。
4. **fact_lookup**：含偏好/属性词（你喜欢/你的习惯/你知道我/我的生日/我的名字/住在哪/记得我/我常/我一般）。
5. **fuzzy**：以上均未命中（语义模糊）→ 混合召回。

**歧义回退**：多意图命中时，按上面顺序取第一个为主意图；第二意图取次强的非重复意图。无任何命中且 `hasOpenThread === true` → `continue_task`（"当前任务"回退）；无命中且无未结 thread → `fuzzy`。

### 1.3 纯函数、可单测

`resolveIntent` 不依赖 I/O，输入 `cueText` + `hasOpenThread`，输出意图列表。关键词表放模块顶层常量 `INTENT_RULES`，便于扩展与观测。

## 2. 按意图装配器（`src/assembler.ts`）

### 2.1 输入数据源（新增读面）

旧 `buildInjection` 只读 `events` + `openThreads`。新装配器额外读：

| 层 | 来源 | 读取规则 |
|---|---|---|
| facts（active attributes） | `MemoryFactStore.loadAttributes()` 过滤 `status==='active'` 且当前有效（`valid_from<=now<valid_to`） | fact_lookup / fuzzy 主读 |
| self_model（stable） | 注入侧已有的 snapshot，只取 `traits`/`preferences`/`speakingStyle`/`narrative`（stable 版本） | persona 主读 |
| state（当前任务） | 注入侧已有的 state snapshot（`getMode`/`getRelationshipStage` 等） | continue_task 主读 |
| raw_turns | `RawTurnLog` 的窗口读取（历史回放用原文） | history_replay 副读 |

### 2.2 装配策略（对齐契约三表）

| 意图 | 主读层 | 预算分配（占总预算比例） |
|---|---|---|
| continue_task | state → events/facts 展开 | state 60% / 展开 30% / self 0—10% |
| fact_lookup | facts | facts 70% / events 证据 20% / state 10% |
| history_replay | events → raw_turns | events 70% / raw_turns 原文 30% |
| persona | self_model + 少量证据事件 | self 70% / 证据 30% |
| fuzzy | 混合召回（events+facts）→ 回源展开 | 候选 60% / 展开 40% |

### 2.3 配额闸门（替代机械 50%）

装配完成后，逐条过闸门（在字符预算截断之前）：

1. **evidence_group ≤40% 或 ≤2 槽**：同 `evidence_group_id`（events 无该字段时退化为同 source 事件簇）占比不超总预算 40%，或不超过 2 个槽位。
2. **ai_inference ≤30%**（persona 意图除外）：`epistemic_type==='ai_inference'` 的条目占总预算 ≤30%。
3. **总预算 ≤1200 tokens**（p95 口径，按模型可调，默认值放常量 `DEFAULT_ASSEMBLE_BUDGET_TOKENS`）。

### 2.4 输出

```ts
export interface AssembleResult {
  intent: Intent[];
  items: Array<{ kind: 'fact'|'event'|'self'|'state'|'raw'; ref: string; text: string; epistemicType?: string }>;
  text: string;   // 带标签工作记忆（与旧 buildInjection 同款格式，便于 diff）
  stats: { evidenceGroups: number; aiInferenceCount: number; budgetTokens: number };
}
```

## 3. shadow 运行 + feature flag

### 3.1 shadow 机制

`index.ts` 注入调用点（约 565 行 `memory.buildInjection(...)` 与 1222 行 `persona_recall`）改为：

1. 旧路径照常跑 `buildInjection`，产出 `oldText`，**照常注入**。
2. 新路径跑 `assemble(...)`，产出 `newText` + stats，**不注入**。
3. 两者差异（intent 命中、items 数量、文本差异、配额命中）追加写观测文件 `~/.dsh/persona-innate/shadow/assembler-<date>.jsonl`。
4. 新路径任何异常都吞掉（shadow 不阻断热路径），记一条 `{error}` 观测。

### 3.2 feature flag

配置 `inject.useIntentAssembler: boolean`（默认 `false`）。为 `true` 时注入改用新装配器文本、停 shadow；为 `false` 时走旧路径 + shadow。开关只影响注入读面，不碰任何写路径（facts/self_model 的写入逻辑零改动）。

## 4. 测试（`tests/intent.test.mjs` + `tests/assembler.test.mjs`）

**intent.test.mjs**（纯函数，无 I/O）：
1. 时间词/历史词 → history_replay；2. 人格词 → persona（`你是谁` 归 persona）；3. 任务续接词或 hasOpenThread → continue_task；4. 偏好/属性词 → fact_lookup；5. 无命中 + 无未结 → fuzzy；6. 无命中 + 有未结 → continue_task（歧义回退）；7. 多意图命中取前 2 个且不重复；8. 空输入 → fuzzy。

**assembler.test.mjs**（用 mock 数据源）：
1. persona 意图 → self 层为主、预算 ≥70%；2. fact_lookup → facts active 且排除 superseded/expired；3. history_replay → events 为主 + raw_turns 原文；4. ai_inference 超 30% 被配额闸门裁掉（persona 意图不裁）；5. 同 evidence_group 超 2 槽被裁；6. 总预算 ≤1200 tokens 截断；7. 空数据源 → 空文本不抛错。

## 5. 验收

- `npm run build` exit 0；`npm test` 全绿（314 既有 + 新增 intent/assembler 用例）。
- `resolveIntent` 规则覆盖五意图 + 歧义回退，纯函数可单测。
- `assemble` 产出带标签文本，配额闸门三条可证（ai_inference ≤30%、evidence_group ≤40%/≤2 槽、≤1200 tokens）。
- shadow 不切读：注入文本仍由旧 buildInjection 产出；差异写观测文件；新路径异常不阻断热路径。
- feature flag 默认 false，切 true 走新路径、切 false 走旧路径。
- 不碰写路径（facts/self_model 写入零改动）。
- git 提交，报告 commit hash 与用例数。
