# 增量5 评测资产化（骨架）实现规格

> 依据：《dsh-memory-architecture-final-design.md》v1.1 §11（验收标准）+ §16.5（增量5）。
> 性质：纯新增文件，不碰任何 `src/` 核心代码。当前 P3-P6 未实施，跑分脚本产出「指标定义 + 空跑占位报告」，等后续施工单元接入真实作答。

## 0. 目标

把最终设计 §11.1 的 140 项 gold set 落成可运行回归资产的最小骨架，作为后续所有施工单元（P3、增量1/2/3/4）的"度量器"。骨架三要素：**标注 schema + 首批样例 + 13 项指标跑分框架**。

## 1. 交付物

1. `goldset/README.md` —— 7 类定义 + 13 指标口径 + 隐藏集分离规则。
2. `goldset/public/` —— 公开集标注文件（JSON）。
3. `goldset/hidden/` —— 隐藏集（规则说明 + 占位）。
4. `scripts/eval-goldset.mjs` —— 跑分脚本（ESM，Node 22+）。
5. `package.json` 加 `"eval:goldset": "node scripts/eval-goldset.mjs"`。
6. `tests/goldset.test.mjs` —— 校验 schema 合法、脚本可跑、指标口径正确。

## 2. 标注 schema（每条 gold item）

```json
{
  "id": "spk-001",
  "category": "speaker",
  "question": "11月3日晚上，谁说'海克斯大乱斗打得怎么样'？",
  "goldAnswer": "user",
  "allowAbstain": false,
  "evidenceEventIds": ["e-001", "e-002"],
  "speaker": "user",
  "timeRange": { "from": "2026-11-03", "to": "2026-11-03" },
  "validity": "active"
}
```

字段说明：
- `id`：类别前缀 + 三位序号（speaker→`spk`、relative_time→`rel`、knowledge_update→`upd`、contamination→`ctm`、abstention→`abs`、persona_stability→`per`、association→`asc`）。
- `category`：七选一。
- `question`：可复现的最小问法。
- `goldAnswer`：speaker 类为 `"user"|"assistant"|"system"|"tool"`；其余类为自由字符串（如正确答案、应弃权标记）。
- `allowAbstain`：true 时"弃权"也是可接受的答案（对应 abstention 类与不可回答项）。
- `evidenceEventIds`：gold 答案的证据事件 id（可为空数组）。
- `speaker`/`timeRange`/`validity`：辅助标注（可空）。

## 3. 七类定义（对应最终设计 §11.1，每类 20 项）

| 类别 | 测什么 | 首批样例数 |
|---|---|---|
| `speaker` | 说话人归属 | 3 |
| `relative_time` | 相对时间归一化/区间（"昨天"不二次偏移） | 3 |
| `knowledge_update` | 知识更新（新旧值取代，superseded 旧值不当当前） | 0（占位） |
| `contamination` | 错误/污染事实识别（quarantined 不注入、AI 疑问不当用户事实） | 0（占位） |
| `abstention` | 不可回答正确弃权 / 可回答不误弃权 | 0（占位） |
| `persona_stability` | 人格稳定（稳定特质一致率） | 0（占位） |
| `association` | 关联查询（10 单跳 + 10 多跳） | 0（占位） |

> 首批只填 speaker 3 + relative_time 3，其余 5 类留空占位（后续施工单元各自填充对应切片）。样例须脱敏/合成，取自最终设计 §12 症状表的最小案例（如"AI 疑问句被当用户事实"→ speaker 类样例；"昨天二次偏移"→ relative_time 类样例）。

## 4. 13 项核心指标（对应最终设计 §11.2）

跑分脚本统计 **1-11（准确性类）**，**12-13（成本类）**留占位接口：

| # | 指标 | 阈值 |
|---|---|---|
| 1 | speaker 归属准确率 | ≥95% |
| 2 | 相对时间归一化/区间正确率 | ≥95% |
| 3 | 知识更新正确率 | ≥95% |
| 4 | superseded 旧值被当作当前事实次数 | =0 |
| 5 | quarantined/已知错误事实进入注入比例 | =0 |
| 6 | AI 疑问冒充用户事实 | =0 |
| 7 | 不可回答项正确弃权率 | ≥90% |
| 8 | 可回答项错误弃权率 | ≤10% |
| 9 | 被污染候选特质注入次数 | =0 |
| 10 | 稳定特质一致率 | ≥90% |
| 11 | 派生事实证据链接可解析率 | =100% |
| 12 | p95 输入 token 相对 events-only 基线增幅 | ≤15% |
| 13 | p95 端到端延迟增幅 | ≤20% |

## 5. 跑分脚本接口与输出

```
node scripts/eval-goldset.mjs [--category speaker] [--hidden 0|1]
```

- 默认跑 `goldset/public/` 全部类别，输出 JSON 报告到 stdout。
- `--category` 过滤单类；`--hidden 1` 才跑隐藏集（默认 0，物理隔离）。
- 报告结构：
  ```json
  {
    "runId": "...",
    "date": "2026-11-05",
    "categories": { "speaker": { "total": 3, "answered": 0, "metric1": {"value": null, "threshold": 0.95, "pass": null} } },
    "summary": { "metrics": { "1": {"value": null, "threshold": 0.95, "pass": null} }, "note": "空跑：当前无被测实现，准确性指标均为未测" }
  }
  ```
- 当前阶段（无被测实现）脚本必须能**空跑成功**：读入样例、按类别聚合、输出"未测（null）"的指标框架，不报错。指标 12/13 永远输出 `{"value": null, "note": "成本指标待系统跑通后接实测"}`。

## 6. 关键约束

1. **纯新增**：不改任何 `src/` 文件、不改既有测试。
2. **隐藏集物理隔离**：`goldset/public/` 与 `goldset/hidden/` 分开目录，默认只跑 public。
3. **不伪造数字**：当前无被测实现，准确性指标一律 `null`（"未测"），严禁填预估值（对应最终设计 §14"未测项保持未验证，不得填写预估值"）。
4. **测试自验**：`tests/goldset.test.mjs` 至少覆盖——schema 合法（7 类枚举、id 前缀）、跑分脚本空跑 exit 0、指标阈值与 §11.2 一致、`--category` 过滤生效。
5. **`npm test` 保持全绿**（现有 280 + 新增 goldset 用例）。

## 7. 验收

- `npm run eval:goldset` 空跑 exit 0，输出 JSON 报告（准确性指标 null、成本指标占位）。
- `npm test` 全绿。
- `goldset/README.md` 说明 7 类 + 13 指标 + 隐藏集规则，与最终设计 §11 一致。
- git 提交，报告 commit hash。
