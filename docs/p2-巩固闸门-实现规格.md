# P2 巩固闸门 · 实现规格

> 依据《记忆架构最终设计 v1.0》§10 迁移计划 P2 行 + §4.4 self_model 晋升门槛 + §5 契约二。
> 状态：待确认后实施。本规格聚焦「self_model 晋升冻结 + candidate 隔离 + G1 最小选材闸门」，完整 G2 七态/G3 注入过滤与证据组留 P3/P4。

---

## 0. 目标与边界

**目标**：落地 ADR-2「self_model 晋升冻结与闸门」，堵住 P0-5「巩固污染闸门缺失」——即 AI 的负面/正面自述被复盘单次提炼就直接固化为稳定特质。

**根因（已核实）**：`src/self-model.ts:113` `const traits = [...new Set([...current.traits, ...(diff.traits ?? [])])]` —— `commitFromSources` 把 `diff.traits` 无条件并入 `current.traits`，没有任何晋升门槛。`reflectSelf`（review.ts:158）用 LLM 从当日事件提炼 traits，prompt 只说「必须可由当日事件支持」，无跨事件/跨会话/非 AI 独白门槛。

**P2 边界（红线）**：
1. 只做 **traits 的晋升闸门**；preferences / speakingStyle / narrative / relationshipView **不动**（它们不是「特质」，且改动面大、风险高）。
2. 不做 facts 七态完整 schema（P3）、不做 attributes 接注入（P4）。
3. 完整 §4.4 门槛依赖 trait 级证据（evidence_group_id / contrary_evidence_ids），现有 `diff.traits` 是纯 `string[]` 无证据映射——**这些留 P3**，P2 用现有字段做**保守近似**（见 §4）。

**验收（对齐 §10 P2 行，标注 P2 可验范围）**：
- 「candidate 不晋升」：未过门槛的 traits 落入 `candidateTraits`，**绝不进入** `current.traits` 注入槽。（P2 可验）
- 「污染项带原因可审计」：晋升/隔离决策带 `reason` 字符串落盘。（P2 可验）
- 「quarantined 不注入」：**P2 不做**（attributes 尚未接注入，无注入可滤；留 P4 装配器）。

## 1. 数据模型（`src/types.ts` 最小扩展）

`SelfModelSnapshot` 增加一个字段（additive，向后兼容）：

```ts
export interface SelfModelSnapshot {
  // ...现有字段不变...
  /** P2：候选特质（未过 §4.4 晋升门槛，只保留不注入） */
  candidateTraits?: string[];
}
```

**语义**：
- `traits` = 稳定特质（stable，注入槽可见）。
- `candidateTraits` = 候选特质（candidate，落盘保留、可审计，但**不进注入**）。

## 2. 晋升门槛（§4.4 的 P2 保守近似）

新增纯函数（建议放 `src/promotion.ts` 或 `src/self-model.ts` 内，独立可单测）：

```ts
export interface PromotionDecision {
  /** 是否允许这批 traits 晋升为 stable */
  promote: boolean;
  /** 可审计的决策理由（无论晋升与否都必须非空） */
  reason: string;
}

export function decidePromotion(
  candidateTraits: string[],
  reflectEvents: readonly PersonaEvent[],
): PromotionDecision;
```

**P2 规则（保守，用现有字段近似 §4.4 的 4 条中的 2 条）**：
1. `candidateTraits` 为空 → `{ promote: false, reason: '无候选特质' }`。
2. **≥1 非 AI 独白来源**（§4.4 条件 3）：`reflectEvents` 中至少 1 条 `provenance === 'user_direct'`。
3. **跨 ≥2 个日期**（§4.4 条件 2 的「日期」近似）：`reflectEvents` 的 `time.slice(0,10)` 去重后 ≥2 个不同日期。

两个条件**同时满足**才 `promote: true`；否则 `promote: false`，`reason` 写明缺哪条。

**为什么这是「保守近似」而非完整 §4.4**：§4.4 的「≥3 独立证据组」「无未解反证」需要 `evidence_group_id` / `contrary_evidence_ids`（P3 才补）；而「跨会话」在 events 层没有 session 字段（raw_turns 的 session_id 是 P1 刚加的，但 events 尚未关联 raw_turns，关联是 P3）。故 P2 用「跨日期」近似「跨会话」。

**预期效果（符合 ADR-2「默认冻结」）**：复盘是增量窗口（游标开区间），单次窗口几乎都落在同一天 → `crossDate` 恒 false → **traits 默认不晋升、进 candidate**。这是刻意的：P2 宁可慢、不污染；P3 补齐证据组后晋升才恢复（且更有依据）。

> 注意：该门槛对**负面自述与正面自述对称**——「我记忆好乱」和「我记性很好」同受此门槛限制（§4.4 对称规则）。

## 3. 实现落点

### 3.1 `src/self-model.ts` —— 支持 candidate 写入

- `commitFromSources` 的 `traits` 合并逻辑（line 113）**不变**（`diff.traits` 仍然只写 stable）。
- 新增方法：`commitCandidates(candidates: string[]): Promise<SelfModelSnapshot>` —— 把候选特质去重合并进 `current.candidateTraits`（不碰 `current.traits`），版本号 +1、旧 current 入 history（与 commitFromSources 同规则），`changeNote` 记 `晋升隔离：N 条候选特质待验证`。

### 3.2 `src/review.ts` —— run() 里加闸门分流（step3 与 step6 之间）

现有流程：`selfDiff = reflectSelf(...)` → `commitFromSources(diff, ...)`。

改为：
1. `reflectSelf` 产出 `selfDiff` 后，取 `selfDiff.traits`（若有）。
2. 调 `decidePromotion(selfDiff.traits, reflectEvents)`。
3. **promote=true** → `selfDiff.traits` 保留，走原 `commitFromSources` 晋升 stable。
4. **promote=false** → 从 `selfDiff` 中**移除 traits**（`delete selfDiff.traits`），并调 `commitCandidates(selfDiff.traits)` 落 candidate；其余字段（preferences/speakingStyle/narrative/relationshipView）**仍照常 commit**（它们不受 traits 门槛约束）。
5. 决策 `reason` 记入 `out` 的审计信息（见 §4 审计报告）。

### 3.3 注入只读 stable（G3 最小闸门）

traits 的注入发生在 `src/index.ts`（约 line 634，`self:[...preferences, ...snap.traits]`），只引用 `snapshot.traits`；`getInjectionSummary`（self-model.ts）读 speakingStyle/narrative/relationshipView，也不含 traits。两处都不引用 `candidateTraits`，故候选特质天然不注入。**无需改代码**，只需在测试里断言：candidateTraits 不出现在注入文本里。

### 3.4 G1 最小选材闸门（可选，低风险）

`distillFacts`（review.ts:138）的 `listing`（line 139）当前不含 provenance。为让 LLM 不把 AI 自述当用户事实，把 listing 改为带来源标注：

```
- [id] (topic) [provenance:user_direct|self_direct|...] summary
```

并在 `distillFacts` prompt 加一句约束：「`type=user` 的事实只能从 `provenance=user_direct` 的事件提炼；`provenance=self_direct/self_correction/induced` 只能提炼为 `type=self`，不得当作用户事实」。

> 此改动小、纯 prompt 层，直接缓解 P0-2「AI 疑问句被当用户事实」。

## 4. 审计报告（污染项带原因可审计）

`ReviewOutput` 增加一个可选字段（additive）：

```ts
/** P2：本次 traits 晋升/隔离决策 */
promotion?: { decision: PromotionDecision; candidateCount: number };
```

`/persona review` 命令的展示（index.ts 复盘结果渲染处）追加一行决策理由，让「为什么这条特质没晋升/晋升了」可查。

- 平台猜测 attribute「聊天平台使用历史=切换至网页端」已在 Phase 0 标 `superseded` + `quarantineNote` ✅。

- P2 后，「我记忆好乱」类新自述经复盘提炼出的 traits 会被 `decidePromotion` 挡进 `candidateTraits`，不再固化。**P2 需在测试里构造这个场景**（见 §6）。

## 6. 测试计划（`tests/`）

1. **decidePromotion 纯函数单测**：
   - 空候选 → false；
   - 无 user_direct → false（纯 AI 独白不晋升，对称含负面自述）；
   - 有 user_direct 但单日 → false（默认冻结）；
   - user_direct + 跨 2 日期 → true。
2. **commitCandidates 单测**：candidateTraits 去重合并、不碰 traits、版本 +1、history 保留。
3. **review run 集成单测**（mock LLM 返回含 traits 的 diff）：
   - promote=false 场景：traits 不进 current.traits，进 candidateTraits，reason 落 out.promotion；
   - promote=true 场景：traits 正常晋升。
4. **注入隔离单测**：`getInjectionSummary` 输出不含 candidateTraits。
5. **回归**：现有全部测试（P1 后 268 条）保持全绿——证明「旧路径行为不变」。
6. **污染场景回归**：构造「我记忆好乱」自述事件 → 复盘 → 断言其 trait 不进入 current.traits。
